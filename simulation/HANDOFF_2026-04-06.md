# Ask2Act Simulation Handoff

Date: 2026-04-06

## What Changed

This branch introduces a clean new primary path for the simulation-side grasp stack under `simulation/ask2act_grasp/`.

Main additions:

- modular package layout for `scene`, `perception`, `grasp`, `planning`, `execution`, and `utils`
- top-level runnable entrypoint at `simulation/pipeline.py`
- runtime MuJoCo scene generation for a table plus a free-body cup
- config-driven head alignment and grasp settings
- fallback point-cloud grasp generation and fallback geometry-aware planning interfaces
- diagnostics script for head pan/tilt behavior under different camera loads
- README updates for GitHub handoff and fresh-machine setup

## What Works

- `simulation/scripts/bootstrap_stretch_mujoco.sh`
- `simulation/scripts/setup_stretch_mujoco.sh`
- `python3 -m pytest simulation/ask2act_grasp/tests -q`
- `cd simulation && python3 pipeline.py --help`
- headless MuJoCo startup with `MUJOCO_GL=egl`
- head pan/tilt motion when cameras are disabled

## Current Blocker

The main blocker on the current VM is performance when RGB-D rendering is enabled:

- without cameras, head pan and tilt reach the requested targets
- with head RGB-D enabled, motion becomes much slower
- with all cameras enabled, motion nearly stalls
- because head alignment does not finish reliably in this environment, the point cloud can be empty and the grasp pipeline cannot yet proceed end-to-end

This looks much more like an environment bottleneck than a pure control bug.

## First Commands To Run On A Stronger Linux Machine

```bash
cd ask2act/simulation
./scripts/bootstrap_stretch_mujoco.sh
python3 scripts/diag_head_motion.py --camera-profile none --timeout-s 20
python3 scripts/diag_head_motion.py --camera-profile head --timeout-s 20
python3 pipeline.py --headless
```

## What To Look For

Good signs:

- `diag_head_motion.py --camera-profile head` reaches close to `head_pan=-1.57` and `head_tilt=-0.55`
- `pipeline.py --headless` produces a non-zero point cloud count
- head camera visibly faces the table and cup

If GUI is available, a useful manual check is whether the robot starts with the D435i already looking toward the tabletop and whether the cup appears in the rendered head view.
